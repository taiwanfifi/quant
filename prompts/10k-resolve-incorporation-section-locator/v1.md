  LLM fallback for finding the section in a DEF 14A Proxy that corresponds to
  a 10-K item flagged as incorporated_by_reference. Used only when regex on
  known section titles fails (~30% of cases).

  Why this prompt is short: by the time we reach LLM fallback, we already know:
    1. The exact item we're looking for (e.g., "Item 11. Executive Compensation")
    2. The Proxy is the right document (we picked it via filing date proximity)
    3. The expected section title patterns (we passed them in the prompt)
  So the LLM's job is just to identify the section's char range in plaintext.

# Prompt

```
You are reading a SEC DEF 14A Proxy Statement.

Find the section that corresponds to "Item {item_number}: {item_title}" of the company's 10-K (which incorporates this Proxy by reference).

Common Item-to-Section mappings:
- Item 10 → Election of Directors / Corporate Governance / Directors and Executive Officers
- Item 11 → Executive Compensation / Compensation Discussion and Analysis
- Item 12 → Security Ownership / Beneficial Ownership
- Item 13 → Related Person Transactions / Director Independence
- Item 14 → Principal Accountant Fees / Audit Fees

Proxy plaintext (first 60K chars):
---
{snippet}
---

Return ONLY a JSON object:
{
  "found": true | false,
  "section_title": "the section header you identified",
  "approx_start_char": 12345,
  "approx_end_char": 23456,
  "evidence_quote": "first 100 chars of the section"
}

If you can't find the section, return {"found": false}.
```

## Empirical performance

- Regex Tier A hits: 4/4 cases on AAPL Items 10-14 (CD&A, Security Ownership, etc.)
- LLM Tier B fallback used: 0 times in golden suite (regex sufficient)
- Estimated LLM cost when triggered: ~$0 (Gemini cookies)

## Observed failure modes

- Older Proxies (pre-2010) sometimes have section titles in ALL CAPS without standard phrasing
- Some companies bury Items 10-14 content within "Other Information" sections — LLM can mis-locate
